# P5.1 implementation review and remediation handoff

## Status and authority

This document records the review of the P5.1 implementation commits in the
inclusive history range `d4bec57` through `d858303` on 2026-08-12. The wider
user-supplied range ends at `a5db4f2`; P5.2 and non-feature commits in that
range are classified separately in the
[P5.2 remediation review](p5.2-remediation-review.md). This is a static review
and implementation handoff, not a second capability ledger. The
[implementation roadmap](../../implementation-roadmap.md) remains the sole owner of
current status and acceptance state. The
[interface specification](../../../design/interface-specification.md),
[Chapter 5 guide](../../../guides/chapter-5-elliptic-control.md), and
[v1 semantic compiler contract](../../../implementation/v1/semantic-compiler.md)
remain authoritative for semantics and lowering.

The P5.1 operator assembly has landed, but P5.1 is not acceptance-complete.
Two implementation findings must be corrected:

1. `P5.1-R1` – give every general scalar coefficient and Robin datum a
   truthful semantic space and region; and
2. `P5.1-R2` – replace prose-only boundary, conormal, transport, and trace
   selections with typed policies that the lowerer actually consumes.

The review also records one commit-integrity problem, `P5.1-R3`. Existing
history must not be rewritten without explicit user authorization; the
finding governs the repair commits and future capability staging.

## Review scope and retained behavior

The review covered:

- `d4bec57` – semantic general-scalar and Robin components;
- `502948d` – deal.II operator assembly and nonsymmetric solves;
- `d6f0730` – compiler routing, bindings, manifest, and focused tests; and
- `d858303` – P5.1 completion documentation.

The following commits in the wider requested range are not P5.1
implementation evidence:

- `2229373` changes repository workflow policy;
- `17c6f6d` through `fec79df` implement and document P5.2; and
- `a5db4f2` records broader application/UI direction.

The remediation must preserve the behavior that static inspection found
consistent with the declared weak form:

- tensor diffusion assembles
  $`(A\nabla y,\nabla v)_{\Omega}`$;
- conservative transport assembles
  $`-(y,b\mathbin\cdot\nabla v)_{\Omega}`$;
- advective transport assembles
  $`(c\mathbin\cdot\nabla y,v)_{\Omega}`$;
- reaction assembles $`(r y,v)_{\Omega}`$;
- the Robin contribution is
  $`(h y,v)_{\Gamma_{R}}-(g,v)_{\Gamma_{R}}`$ in the residual;
- the conormal convention is
  $`(A\nabla y-b y)\mathbin\cdot n_{\mathrm{out}}`$;
- fixed-Dirichlet and Robin boundary IDs are required to be disjoint and to
  cover the compiled exterior mesh;
- the state operator is allowed to be nonsymmetric and the adjoint uses the
  exact transpose of the same `SparseDirectUMFPACK` factorization; and
- volume control, full-volume tracking, the cellwise $L^{2}$ metric, and the
  optional cellwise box retain their existing independent components.

The focused P5.1 tests isolate nonzero contributions from every
state-dependent term, check JVP/VJP pairings, verify the Robin source has zero
derivative, expose nonsymmetry, exercise a reduced Taylor remainder, and
check mesh-boundary and coefficient-shape diagnostics. Those are useful
regression tests and must remain.

No build or test command was run during this static review. The review relied
on the committed tests and direct inspection of the semantic graph, lowering
plan, compiler, backend assembly, and manifest generation.

## P5.1-R1 – coefficient and Robin data have missing or wrong regions

**Severity:** P1 – blocks P5.1 acceptance because the semantic graph and
manifest do not describe where the executable evaluates its immutable data.

### Evidence

The interface specification requires every datum to declare its space,
region, field shape, and source. The P5.1 reference factory currently creates
the following declarations in
[`reference_specs.hpp`](../../../../include/nmopt/semantic/v1/reference_specs.hpp):

- tensor diffusion has an empty `space_id`;
- conservative and advective vector transport have empty `space_id` values;
- the scalar reaction Function has an empty `space_id`;
- the Robin coefficient has an empty `space_id`; and
- the Robin source points to `state_test_space`, whose base region is the
  volume `domain`, even though the source is evaluated on `robin_boundary`.

`SemanticValidator::validate_data()` checks only that a nonempty `space_id`
exists and that the `DataKind` matches the coarse coefficient role. It does
not require the expected volume or boundary region. The residual-term
signature checks verify roles and port counts but do not match a Robin
datum's space region to the residual term's boundary region.

The executable therefore supplies information absent from or contrary to the
graph. `ScalarComponentModel::assemble_physical_operators()` evaluates tensor,
transport, and reaction Functions at volume quadrature and evaluates the
Robin coefficient/source at face quadrature selected from the Robin term.
Manifest generation repeats those hard-coded placements in prose. It does
not derive them from resolved semantic data spaces.

This is not merely incomplete documentation. A graph can move the Robin
source to an unrelated declared volume space, or leave every coefficient
unspaced, and still reach the same backend computation. The compiled product
then claims to preserve a component graph whose data ports did not select the
executed domains.

### Required semantic outcome

Every P5.1 Function datum must resolve to a semantic space on the region where
the backend evaluates it. The bounded declaration needs at least:

| Datum | Field shape | Required base region | Required topology or assumption |
| --- | --- | --- | --- |
| tensor diffusion | rank-two tensor | full volume `domain` | bounded coefficient with the separate uniform-ellipticity assumption |
| conservative transport | vector | full volume `domain` | bounded/Lipschitz coefficient as declared by the regularity policy |
| advective transport | vector | full volume `domain` | bounded coefficient as declared by the regularity policy |
| reaction | scalar | full volume `domain` | bounded scalar coefficient |
| Robin coefficient | scalar | `robin_boundary` | boundary $L^{\infty}$ coefficient |
| Robin source | scalar | `robin_boundary` | boundary $L^{2}$ datum for the selected trace pairing |

Do not label an $L^{\infty}$ coefficient space as $L^{2}$ merely because the
current `SpaceTopology` enum lacks a bounded-function entry. Make the smallest
deliberate semantic extension needed to state the selected spaces truthfully.
One bounded option is to add an explicit bounded-function topology and reuse
`DataKind` for scalar/vector/tensor shape. Another is a typed data-domain
payload referenced by `DataSpec`. Whichever representation is chosen must be
documented in the interface specification and v1 compiler contract in the
same work unit.

The resolved graph must establish all of these relations without consulting
`ProblemSpec::id`, labels, or `DataRole` alone. A human-readable binding
description may render the resolved record, but it must not be the source of
placement.

### Implementation instructions

1. Introduce the minimal backend-neutral representation for the volume and
   boundary coefficient/data spaces. Preserve stable existing component IDs
   where possible.
2. Update `make_general_scalar_elliptic_robin_problem()` so every P5.1
   Function datum references the correct semantic space and base region.
3. Extend semantic validation with exact checks for:
   - coefficient field shape and topology;
   - full-volume placement of tensor diffusion, transports, and reaction;
   - Robin-boundary placement of the coefficient and source;
   - equality between each Robin datum's region and its owning term's
     `region_id`; and
   - the Robin source's compatibility with the selected boundary trace
     pairing.
4. Use stable diagnostics. Suggested capability names are
   `coefficient_data_space`, `volume_coefficient_region`,
   `robin_coefficient_region`, `robin_source_region`, and
   `robin_source_trace_pairing`.
5. Copy the resolved placements into `ScalarLoweringPlan`. The plan should
   expose a typed placement/handler record rather than force the backend to
   rediscover placement from an enum.
6. Make P5.1 model construction consume and check the resolved plan. The
   backend may keep its bounded volume/face assembly loops, but construction
   must fail before assembly if the plan requests another placement.
7. Extend `CompiledBindingRecord`, or add a structured companion record, so
   the manifest records each binding's semantic space ID, region ID, field
   shape, evaluation realization, and provenance.
8. Generate `data_rule` prose from those structured records instead of
   independently hard-coding the P5.1 placement description.
9. Update the authoritative interface and v1 compiler documents. Keep
   uniform ellipticity and coefficient regularity as model-author
   assumptions; do not claim that the compiler proves them from sampled
   Function values.

### Required tests

Add backend-neutral mutations of the valid P5.1 graph for:

- each empty coefficient `space_id`;
- tensor or vector coefficient data placed on `robin_boundary`;
- Robin coefficient data placed on `domain`;
- Robin source data left in `state_test_space`;
- Robin source and Robin bilinear terms referencing different boundary data
  regions; and
- a valid graph whose IDs and labels are changed while its typed ports remain
  intact, proving that placement is structural.

Each invalid mutation must produce one exact diagnostic at semantic
validation or lowering, before deal.II model construction. Add a positive
lowering-plan test that checks the typed placement of all six P5.1
coefficient/source bindings.

Extend the deal.II contract to assert that every structured manifest binding
contains its semantic space and region and that the Robin records name the
same selected boundary as both Robin residual terms. Preserve the existing
shape, provenance, term-isolation, transpose, and Taylor tests.

## P5.1-R2 – boundary and conormal policies are prose-only selections

**Severity:** P1 – blocks P5.1 acceptance because the compiler can silently
execute its built-in boundary interpretation after accepting a different
declaration.

### Evidence

P5.1 requires a boundary-partition policy distinguishing fixed Dirichlet,
Neumann, Robin, transport inflow, and transport outflow regions, together
with an explicit conormal convention and trace interpretation. The first
registered target deliberately selects:

- one fixed-Dirichlet region;
- one Robin region that is also the natural transport-outflow region;
- no Neumann region; and
- no separate transport-inflow region.

The graph currently encodes the roles after the first two almost entirely in
`RequirementPolicySpec::selected_policy` prose. The generic semantic helper
accepts a selected policy from its subject and `RequirementKind` when the
display string is merely nonempty. Scope is not part of that selection. The
compiler independently finds fixed and Robin IDs from other components,
checks disjointness and mesh coverage, and the backend always assembles:

```math
(A\nabla y-b y)\mathbin\cdot n_{\mathrm{out}},
\qquad
\text{Robin region}=\text{natural transport-outflow region},
\qquad
\text{`FE_Q` trace at face quadrature}.
```

Consequently a selected policy can contain an inward-normal conormal, an
alternate transport-boundary interpretation, a different trace rule, or the
wrong scope while validation and lowering still execute the hard-coded
outward face-quadrature target. The manifest appends the user's prose after
construction, so it can record a declaration that contradicts the model.

The `boundary_partition` requirement also does not structurally own the
partition roles. Mesh checks prove that the two ID sets cover the exterior,
but not that a typed semantic selection assigned Robin, outflow, and the empty
roles as the backend assumes.

### Required outcome

Replace capability-bearing P5.1 prose with typed, backend-neutral selections.
The minimum closed payload must identify:

- fixed-Dirichlet region ID;
- Robin region ID;
- Neumann region selection, explicitly empty for this target;
- transport-inflow region selection, explicitly empty for this target;
- transport-outflow region ID, equal to the Robin region for this target;
- conormal operator form and sign;
- outward normal orientation;
- Robin state-trace realization;
- face quadrature realization ID; and
- status and scope appropriate to the continuous declaration and selected
  discrete realization.

Use `selected_policy` only to render the typed selection. Do not parse or
compare English substrings. Coordinate the shape of this policy with the
[P5.2 selected-realization repair](p5.2-remediation-review.md#p52-r1--selected-p52-realizations-are-not-executable-contracts)
and the existing P5.3/P5.4 typed-policy work so that boundary orientation,
trace quadrature, and realization IDs have one vocabulary.

### Implementation instructions

1. Add the smallest common typed policy types needed for boundary partition,
   normal orientation, conormal form, transport-boundary role, and trace
   evaluation. Do not add a scalar-PDE or Robin-problem enum.
2. Populate the exact first P5.1 registration in the reference factory.
3. Validate every referenced region, exact role, disjointness relation,
   status, scope, and equality between Robin and selected outflow regions.
4. Reject alternate typed conormal signs, orientations, trace realizations,
   or nonempty Neumann/inflow roles with one exact lowerability diagnostic.
5. Make `DealiiScalarLoweringPlanner` carry the resolved selection into the
   plan. Remove any dependency on display text for capability.
6. Make the compiler's mesh-coverage checks consume the resolved partition
   rather than recomputing a different partition from incidental terms and
   policies.
7. Make model construction receive the resolved normal/trace selection and
   assert that it matches the bounded face assembly.
8. Add a structured boundary/conormal record to the manifest and render
   existing prose from it.
9. Update the v1 compiler capability table and exclusions. Alternate
   Neumann, inflow, mixed, and trace rules remain rejected unless separately
   registered later.

### Required tests

Add table-driven semantic/compiler mutations for:

- missing typed boundary partition;
- wrong fixed or Robin region reference;
- a nonempty Neumann role in the first P5.1 registration;
- a separate transport-outflow region;
- a nonempty transport-inflow role;
- inward normal orientation;
- the opposite conormal sign;
- an unsupported trace or quadrature realization;
- wrong policy scope or status; and
- arbitrary changes to display strings with no change in lowering behavior.

For the valid target, assert that the lowering plan, executable assembly
selection, manifest record, and mesh coverage diagnostic all use the same
region IDs, orientation, conormal form, and trace realization. Keep the
existing test that explicitly demonstrates nonsymmetry and exact transpose
behavior.

## P5.1-R3 – capability publication preceded executable registration

**Severity:** P2 process finding – does not require a history rewrite.

### Evidence

`d4bec57` was described as a semantic declaration commit, but it also changed
`DealiiCapabilityRegistryV1` to return `true` for every new P5.1 residual kind
and registered scalar-plan handlers. The registry's own contract says a kind
is executable only when the compiler has registered the corresponding
lowerer. At that historical point:

- the semantic graph and scalar plan existed;
- P5.1 deal.II assembly did not exist until `502948d`; and
- compiler routing, binding validation, manifest generation, and executable
  tests did not exist until `d6f0730`.

Other graph-wide checks happened to prevent the new graph from successfully
compiling before `d6f0730`, but the public capability registry and scalar
planner already advertised lowerers. That is a misleading intermediate
state and could have become an executable fall-through after an unrelated
validation change.

### Required process outcome

Do not rewrite these commits without explicit authorization. For future
semantic staging:

- keep new capability-registry entries disabled until the executable route,
  exact diagnostics, bindings, manifest, and focused tests land together; or
- use a clearly named semantic/planning registry whose contract does not claim
  executable support.

The remediation commit that enables a new typed P5.1 realization must include
its exact registration check, backend consumption, truthful structured
manifest, and focused positive/negative tests. Do not create an intermediate
commit that marks the new selection lowerable while the backend ignores it.

## Acceptance checklist

P5.1 can return to `completed` only when all of the following are true:

- [ ] every P5.1 coefficient/source datum has a truthful semantic space,
      region, and field shape;
- [ ] the Robin source is no longer declared in the volume test space;
- [ ] semantic validation rejects every wrong coefficient/Robin placement;
- [ ] a typed boundary partition names fixed, Robin, Neumann, inflow, and
      outflow roles, including the selected empty roles;
- [ ] conormal sign, normal orientation, trace, and quadrature selections are
      typed and no capability depends on prose;
- [ ] the same resolved selection drives mesh checks, model construction, and
      structured manifest records;
- [ ] display-text mutations do not change compiler behavior;
- [ ] existing term-isolation, Robin-source, nonsymmetric transpose, reduced
      Taylor, binding, and mesh-boundary tests still pass;
- [ ] the complete neutral and deal.II Debug profiles pass; and
- [ ] the roadmap alone is updated to mark P5.1 acceptance complete.
